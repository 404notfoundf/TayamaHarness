## 2. 模块职责与依赖方向

```
Controller → Service → Repository → Model / ORM
                  ↓
           外部 API / LLM / 基础设施
```

- **依赖单向**: `Controller → Service → Repository → Model`，禁止反向（Model 不依赖 Service）
- **Service 是最核心**：业务规则、事务边界、领域事件
- **Repository 隔离数据源**：ORM 查询封装在 Repository（或用 Eloquent Model 直查但禁止业务逻辑）
- **Controller 是薄层**：解析请求、校验输入、调用 Service、映射响应，禁止放业务逻辑

## 3. 模块组织约定

| 规则 | 说明 |
|------|------|
| 一个功能一个模块 | 按领域聚合到 `Services/` 下子目录，不按技术层堆叠 |
| 命名空间 | PSR-4，`App\` 对应 `app/`；禁止类名与命名空间不一致 |
| 循环依赖 | 禁止（Service ↔ Service 相互调用需重构，用事件/中间件解耦） |
| 服务注册 | 依赖注入容器（Laravel service provider / 框架容器）统一注册 |

### 3.1 典型 Service 结构

```php
namespace App\Services\Budget;

class BudgetService
{
    public function __construct(
        private readonly BudgetRepository $repo,
        private readonly CostEstimator $estimator,
    ) {}
}
```

## 4. 错误处理结构

```
app/
└── Exceptions/
    ├── AppException (基类, code + message + context)
    ├── DomainException
    └── ExternalServiceException
```

- 业务错误抛 `AppException` 子类（带业务错误码），Controller 统一 catch 并映射 HTTP 状态码
- 禁止在 Service/Controller 中裸 `catch (\Exception)` 吞错返回 null
- 外部调用失败 → `ExternalServiceException`，上层决定降级而非静默

## 5. 文件组织约束

| 约束 | 规则 | 守护手段 |
|------|------|---------|
| 文件长度 | ≤ 500 行 | phpstan / 人工 |
| 方法长度 | ≤ 50 行 | phpstan / 人工 |
| 圈复杂度 | ≤ 10 | phpstan (cyclomatic) |
| 依赖审计 | 0 高危漏洞 | composer audit |
| 类型 | 全量 strict_types | phpstan / psalm |
| 未使用 | 禁止死代码/未用 import | phpstan |

## 6. 新增模块/feature 的目录约定

- 新领域模块 → `app/Services/<Domain>/` + `Models/` + `Repositories/`
- 新 API 端点 → `routes/api.php` + `app/Controllers/` + DTO 对齐契约
- 新数据源 → `Repositories/` trait/实现 + `database/migrations/`
- 新需求 → 在 `.harness/changes/<id>/` 建档
## 7. 架构审查关注点（arch-review 引用的语言特有检查项）

- **Controller 厚度** — Controller 是否塞了业务逻辑（应为薄层）？
- **Service 边界** — Service 是否按领域聚合，还是按技术层堆叠？
- **{{FRAMEWORK_NAME}} 布局** — 是否符合框架约定（Laravel app/、Symfony src/、ThinkPHP app/ 等）？
- **依赖注入** — 是否用容器/构造注入，还是静态 facade/new 满天飞（可测性差）？
- **错误处理** — 是否有吞错（空 catch）、裸 throw、错误码缺失？
- **类型安全** — 是否 strict_types + 强类型宣言，还是"/** @var */ 掩盖"满天飞？
