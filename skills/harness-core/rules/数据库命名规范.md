# 数据库命名规范

> **作用域**: 关系型库的表、列、索引、约束**怎么起名**（不含 Redis key；类型/精度见 `/harness-db-design`）。
> **状态**: 强制
> **执行者**: `/harness-db-design`、`database-migration-toolkit`、`/coding-skill`
> **事实源**: 库列 → `.harness/wiki/数据模型.md`；术语 → `.harness/CONTEXT.md`

## 快速对照

| 对象 | 默认 |
|------|------|
| 表名 | snake_case、单数；避开 SQL 保留字裸名 |
| 列名 | snake_case；外键 `{实体}_id` |
| 时间 / 软删 | `created_at` / `updated_at`；`deleted` |
| 索引 | `uk_{表}_{列}` / `idx_{表}_{列}`（列名原样拼接） |
| 中间表 | `{主}_{从}` |

## 命名流程

读 CONTEXT → 读 wiki 存量风格 → 新名写入 wiki → 再迁移/编码。无词表依据的缩写、未入 wiki 的字段名禁止落库。

---

## 1. 表名

- 小写 snake_case，默认单数（`sku`）。禁止驼峰、连字符。
- 与 CONTEXT 一致（SKU → `sku`，禁止 `sk_u`）。存量 wiki 已用复数则跟随，禁止混用。
- 避开保留字裸名（`order`、`user`、`group` 等），加业务前缀（`trade_order`）。
- **中间表**：两端单数 `{a}_{b}`；有主从则主在前。列 `{实体}_id`，联合唯一 `uk_{中间表}_{a_id}_{b_id}`。

---

## 2. 列名

- 仅字母数字下划线。主键默认 `id`。
- 外键 `{被引实体单数}_id`（`sku_id`，禁止未登记的 `sk_uid`）。
- 布尔全库一种：推荐 `xxx_flag`；存量 `is_xxx` 则跟随（实体侧见 `ORM与库表映射.md`）。
- 时间 / 软删：`created_at`、`updated_at`、`deleted`。
- 状态 / 状态机：`status` 或 `{域}_status`；允许值写 wiki 说明、与 CONTEXT 一致。**类型未另行指明时必须用整数**（见 `/harness-db-design`）。
- 禁止：无词表缩写；同一含义两套列名；未入 wiki 即落库。

---

## 3. 索引名

列名原样按下划线拼接，禁止另造缩写（`idx_trade_order_user_id`，非 `idx_uid`）。  
超长（如 MySQL 标识符 64）须在 wiki **显式登记**短名，禁止静默截断出第二套名字。

---

## 4. CONTEXT、wiki、编码

1. 新术语先 CONTEXT / `domain-modeling`，再定名。
2. wiki 表结构是库列事实源；迁移与 SQL 与之逐字一致。
3. 交 `database-migration-toolkit` 与 `/coding-skill` 之前，名字已在 wiki 定稿。禁止只抄 change.md。
4. 应用层字段对照：`ORM与库表映射.md`（若有）+ wiki「ORM 映射」表。

---

## 5. 项目例外

与上文冲突的存量约定，只写在 wiki「命名约定」并注明范围。未写则用本规范默认。禁止无范围地混用两套（如 `created_at` 与 `gmt_create`）。
