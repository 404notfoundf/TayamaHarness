# 当 Harness 不断收缩：FDE 与技术人员的新定位

> Harness 会越来越多地接手"执行"，那么人还剩下什么？
> 本文讨论 Harness 收缩趋势下，技术人员的角色演进——从写代码到 FDE（Forward Deployed Engineer）。

## Harness 收缩意味着什么

随着共性能力与自动化不断成熟，Harness 会像编译器的进步一样，把越来越多的"执行"收进去：编码、测试、评审、发布、排障、归档，逐渐由 Agent 在约束体系内完成。

但有两件事**不会收缩**：

- **业务知识治理**：什么规则成立、什么口径作废、什么决策难逆转，需要人持续裁决；
- **质量责任**：验收、签字、风险授权，责任始终在人。

## 人的角色在迁移

| 传统角色 | 演进方向 |
|---------|---------|
| 逐行写代码 | 定义约束、设计协议、评审关键决策 |
| 手工测试 | 设计验证策略、裁决证据 |
| 手工发布 | 定义发布门禁、确认不可逆操作 |
| 知识经验在人脑 | 把隐性知识显式化，治理知识库 |

## FDE：向前部署的工程师

技术人员的价值从"自己动手产出"转向"让体系对业务落地"——深入业务现场，理解真实问题，把共性能力组装成解决具体业务问题的方案，同时把现场反馈回流给 Harness。这就是 FDE（Forward Deployed Engineer）：**既懂工程体系，又贴近业务现场**。

## 与脚手架的关系

脚手架是"Harness 收缩"的加速器：它把流水线、门禁、知识治理机制固化下来，让人的精力从重复执行释放到决策与治理上。`Owner Agent` 的决策边界（可自主/必须请示/必须停下）正是"人负责决策、Agent 负责执行完整"的落地。

**核心命题**：Harness 收缩的不是人的价值，而是人的重复劳动——技术人员的未来在 FDE：既懂工程，又贴现场。
