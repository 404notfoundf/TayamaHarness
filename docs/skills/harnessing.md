# 需求拷问引擎 — harnessing

> **技能标识**: `harnessing`
> **使用场景**: 被 `/harness-me` 调用，或用户直接要求"帮我理清需求"、"分析这个方案"
> **核心原则**: 一次只问一个问题，沿决策树分支推进

## 它做什么？

需求拷问引擎——一场让你"有点不舒服"的灵魂拷问，帮你把模糊的需求/方案/设计打磨到能落地的程度。

被 `harness-me` 技能调用，或用户直接调用。

## 核心原则

**一次只问一个问题。** 等我回答完再问下一个。同时抛出一堆问题会让人不知所措。

**不要急着给答案。** 你的任务是问更好的问题，而不是替用户想方案。

**沿决策树分支推进。** 每个答案会打开新的问题分支，跟随它。

## 工作流程

### Step 1: 理解当前状态

- 用户想做什么？
- 当前处于什么阶段？
- 有什么已知的约束？

### Step 2: 一次问一个问题

沿决策树推进：

```
"这个需求要解决什么用户问题？"
    ↓（用户回答）
"现有方案有什么痛点？"
    ↓（用户回答）
"这个需求的第一优先级是什么？"
    ↓（用户回答）
"有什么已知的技术约束？"
    ...
```

### Step 3: 输出需求总结

当决策树收敛后，输出结构化的需求总结卡片。

## 什么时候用？

- 用户说"帮我理清需求"
- 用户说"分析这个方案"
- 用户说"这个设计有没有漏洞"
- `/harness-me` 技能调用

## 常见问题

### 问什么样的问题？

- 澄清型："你说的'更好'是指什么维度的更好？"
- 边界型："这个方案覆盖了哪些场景，漏掉了哪些？"
- 决策型："为什么选 A 不选 B？"
- 风险型："如果这个方案不成立，Plan B 是什么？"

### 什么时候停止？

当决策树不再产生新分支，需求已经清晰可落地时停止。
